# Lodestone audit, 2026-10-26: the code since 2026-10-20

**Which code this covers.** This audit covers the whole diff 1f174f6..8e3cc80. That is main with PR #111 merged: about 226 files and 55k lines added. The diff brings:
- multitasking M3-M9 (KMT.INC, MTAPI.INC) and windows (KMW.INC);
- terminal windows T0-T5c (TERM.RUN, TASKS.RUN, MT_PUB, MT_WAKE);
- right-click menus and the clipboard (UI_MENU, UI_CLIP, RMENU.INC);
- resident Claude (RCON, OPS.INC, PROF.INC, the background screen read, the quadrant glyphs);
- the no-disk INT 24h work and MS-DOS error codes in the file system;
- the GPIB DMA/IRQ tools, the Pico bridge and the plotter Nano.

T5d (CLAUDE.COM in a terminal window) is not in 8e3cc80. The 2026-10-20 audit covered the tree up to 1f174f6. Its PRs (#48, #49, #51, #53, #55, #56) landed inside this range, so §1 gives both baselines.

**How it was done.** Nineteen finders and lenses, each played by a persona:
- KMT: kmt-a, kmt-b, kmt-c; windows: kmw.
- Kernel and UI: kernel, ui, apps, lcmd.
- Claude: claude-a, claude-b, rcon.
- Off the core: gpib-tools, pico-nano, claude-link, tests.
- Cross-cutting: copied-routines, resident-reuse, size-idioms, map-diff.

Four gap lenses added the kernel's error-code block, the resident menu and clipboard, MT's INT 10h emulator, and the link's hot path on both halves.

Each finder did three things in turn:
1. read the diff for its scope;
2. read the current full files;
3. grepped the whole tree for routines the new code copies or could call.

A finder of a different persona then re-checked every finding adversarially: sites, register contracts, byte counts, hazards. The numbers below are the verifiers' corrected ones.

The personas are Jane Street, NASA/JPL, Stripe, Xerox PARC, SpaceX, Google, Apple, IBM, Amazon and Netflix. The Personas column credits every one that raised a row. Rows marked **fixed** name the PR that fixed them.

The finders, verifiers, the completeness critic and the gap round ran on Fable; the two report drafts on Opus 5.5. One exception: a safety classifier stopped one of the ui finder's (Google) Fable responses by mistake. Claude Code then wrote that finder's last turn, its findings list, on Opus 4.8. Its reading and test build had already run on Fable, and its NASA/JPL verifier, on Fable, re-checked every row.

Rows marked **†** were test-assembled in a private WSL copy of 8e3cc80, and the saving was read from the map. The others are counted encodings. Where a verifier also ran a test suite on the build, the Notes say so. Nothing in the code was changed.

**Where the bytes live:**
- **Resident**: DOS programs lose these bytes. That is kernel .text/.bss, the ems and hd modules, the UI below `ui_keep_end`, and the ROM driver's kept part.
- **Stub**: lost to every DOS program while CLAUDE /R is loaded.
- **LCMD-under-child**: lost only to programs started from the prompt.
- **Claude-resident**: lost only while CLAUDE.COM runs a program.
- **RCON page**: headroom in RCON's EMS page, not DOS memory.
- **MT-only**: in LODEMT.SYS; costs nothing with MULTITASK off.
- **Load-image-only** and **file-only**: disk or ROM space.
- **Off-1520 rows** (Pico firmware, the Pi's Python, claude-link): these report reuse, failure modes and link speed. Bytes only count on the Nano (2 KB SRAM, 32 KB flash).

**The user's rule on speed.** Every row states its speed effect. A row is marked **needs the user's yes**, with the cost, when it does any of these:
- slows anything;
- grows the resident cost with MULTITASK off;
- grows LODEMT.SYS.

## 8. Checked and rejected

- **XR-12 (srq_sleep in TERMLINK)**: each binary pays for the shared routine but saves only its own copy, so it costs +3 B in CLAUDE.COM and +5 B in RCON. The smaller srq_look form is R48.
- **MB-14's failure mode** (MT with no UI reading 0:m33_busy): ui_load halts the machine when the UI can't load, and mt_boot runs after it, so ui_seg is never 0 under MT. The shared predicate stays (O18).
- **XI-15 (24-byte task entries)**: TE_GEN and TE_EGEN now fill the 32 bytes. The test half is H6.
- **G1-5's kernel helper** (one last-component scan for the six kernel sites): these are four different operations, and a helper nets +6 B. The MT half became R2.
- **UI-1's shared .RUN loader with run_app**: the copies are not byte-identical (cs: prefixes; BSS vs max(BSS, fixups)), and the headers live in different segments. The "third GR/UN/API copy" does not exist. A routine run_app can reach must live in section ui, which would grow it with MT off. Its sound half is R43.
- **G2-5 (clip_ems's 57h region over tmp, 12 B)**: safe today only through three unenforced invariants (no INT 21h inside, no tmp user from an interrupt, mt_safe refusing KSEG). The stack frame carries none of them.
- **G3-8 (one cell writer for 09h/0Ah and the teletype)**: 6 B for +18 clocks per character, on the hottest emulated paths.
- **MW-12 (mw_size through win_mv with hooks)**: four hooks cost ~20-26 B of resident UI with MT off, to save ~50 B MT-only.
- **UI-3 (mw_span calls row_di by UCALL)**: 6 B for ~+4.5 µs per clipped row, which is several ms per redraw under windows.
- **XR-13 (a bitwise CRC-16, −544 B)**: ~5× slower per byte. RCON's screen_crc also hashes 4,000 B at every HELLO (+50-60 ms a pop-up). R56 removes the same table and is faster.
- **G4-3 (fl16 as a byte loop)**: kept as R57 only for the record; recommend no.
- **LK-6's speed claim** (grid_emu's double bridge service): the call counts are right, but removing it measured 0-3 % wall time, within noise.
- **AP-6's TASKS clamp (8 B)**: not dead under MTAPI's compat rule. A later kernel with more tasks would overrun `recs`.
- **KN-14 (drop the `[X:]\DEV\` prefix, 22 B)**: X18 matched a measured MS-DOS answer (ERRS_MS.TXT:110, 399), and GRiD's GPIB software opens `\DEV\IEEEOUT` (tools/D488TEST.ASM). The user's call; recommend keeping it.
- **CB-11 as written** (`%defstr` on an `equ`): it produced `req=REQMA…` in a test assembly, with no assert firing. The `%if` form is in §0's doc list.
- **KN-3 as written** (the refused mode in AL): h2sft returns AL = the SFT number, so R33 uses CL.
- **XM-3 as proposed** (shrink below convseg/ioseg): f_4B allocates first-fit from the largest block, so the hole never reaches the child. O17 is the reordered form.
- **MC-12's "strong MT_FRONT"**: it can keep a window task out of its full-screen graphics while a stale request waits.
- **MB-8's 38-byte variant**: it couples mt_m33bz and mt_m33nb, so mt_end's swing path would record 0 twice.
- **G2-4 (a click on ui_menu's frame closes it)**: a behaviour change that buys 12 B and no paragraph once R39-R41 are in (5204h vs 5210h, both with ui_keep_end 64E6h).
- **The clip-gate call forms (MW-5 65 B, XS-5 51 B)**: they put a call on every clipped primitive. R18's `cmp word` form saves 48 B and is faster.
- **AP-7's form** (drop TERM's guard and let UI_MENU beep): this changes a T5b decision (test_mt.py:4958-4974 expects no menu). R66 keeps the silence.
- **XI-4's local mt_merge helper** (−91): the KCALL form (R1) is smaller.
- **XM-6's "data does not move"**: LCMD's BSS follows its code and shifts with it. Harmless (the hist overlay is `equ start`), but the claim was wrong.
- **The finder's G2-6 fix** (`cmp dl,'A'+16`): it tests for 'Q', so it never matches, and it would send the clipboard to A: even with a C: present.
