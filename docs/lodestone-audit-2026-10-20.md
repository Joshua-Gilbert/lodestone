# Lodestone audit, 2026-10-20: space and reuse

**Which code this covers.** The audit started from 097d140. The verifiers measured against d126269 … 2a35b4a. While the audit ran, main moved to 1f174f6, which merged PR #47 (the FPU work). So wherever this report says to do something "after the FPU work lands", that work has now landed. KMT.INC line numbers are as of 2a35b4a; at 1f174f6 they are the same or one line off (`mt_carve` 1345, `.mg` 1359, `mt_kwant` 254, `mt_preempt` 376). All of §0 was checked by hand against 1f174f6 and then fixed (marked below). X6 was more than the emulator: three of KROM's four E403 callers reload what they need, but `rm_dosimg` kept E401's image count in CL across it (harmless with two 128 KB sockets, wrong with three or more images); fixed in the same PR, and pcemu now answers BX, CL, DH with the BIOS's own values.

Ten read-only lenses went through the code in parallel, each with a finder and a second agent that re-checked every finding adversarially (sites, register contracts, byte counts, hazards): the resident kernel core, the file system, the kernel modules, the UI core, the apps, the shell and standalone programs, Resident Claude, copied routines across all the assembly, "what is already resident and callable", and 286 idioms and layout. Four gap lenses covered the EMS/drive-module fork (G1), the KMT M3/M3b code (G2), UI API 6 and the .RUN loader (G3) and the Executive's Copy/Move/Erase family (G4).

Sizes come from `LODE.MAP`, `CLAUDE.MAP`, `RCON.MAP` and the apps' `mkrun.py` output. Baselines: `image_end` 44F0h, `kern_top` 0F33h, `bss_end` 7B40h, `ui_image_end` 55FCh, `ui_keep_end` 6CE4h, `ui_bss_end` 8AE4h, LCMD `prog_end` 3D1Ah, CLAUDE `bss_end` 710Fh, `mt_tend` 0C71h (at 2a35b4a). Rows marked **†** were test-assembled in a private copy and the saving read from the map; the others are counted encodings, checked by the second agent. Every figure below is the verifier's corrected one. The verifiers measured against several commits (d126269 … 2a35b4a) and KMT.INC has moved again since (HEAD is 7dd2328 on `claude/mt-fpu`), so KMT line numbers are the verifier's commit's. Nothing was changed in the code.

"Resident" means DOS programs lose those bytes (kernel .text/.bss, the ems and hd modules, the UI below `ui_keep_end`). "LCMD-under-child" bytes are lost only to programs started from the prompt; "Claude-resident" only while CLAUDE.COM runs a program; "MT-only" bytes are in LODEMT.SYS and cost nothing with MULTITASK off; "transient" costs disk and load time; "file-only" costs disk and ROM space. Nothing here grows the MT-off resident cost except where a row says so.

## 5. Checked and rejected

- **UI-13** (replace the Executive's pointer renderer with m33_gfx, 650 B): the copies are not equivalent — compose composes old-erase and new-draw in RAM and writes each screen byte once to avoid the plasma flicker m33_gfx's erase-then-draw produces; the finder itself recommended against it.
- **AP-9** (share CALC's calc_var/setvar env walk with LCMD's env_find): the contracts differ (value pointer vs entry start plus block end); nets +9 to −4 B in CALC.COM, 0 in LCMD; and c_nm is printed in error messages, so an appended '=' would show.
- **CL-14** (n_bad counted and never read): it is read — claude-link/tests/test_emu.py:166 asserts it after corrupting frames; comment both counters instead.
- **XR-11** (export font_file/months/has_drv to the apps): not equivalent copies (different buffers and contracts, uppercase vs mixed-case months); +6 B resident for transient bytes.
- **XR-19** (DEFRAG as a .RUN, 2.8 KB): DEFRAG must run under GRiD MS-DOS (map only) — the prior B4 row already says so; FONT.INC is 1,536 B, not ~2.4 KB; /S already takes the Executive's font via F=.
