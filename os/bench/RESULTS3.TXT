Notes
- File system: Grid-OS is 3.6x faster than both in total. FreeDOS and GRiD
  MS-DOS behave alike: small reads cost a disk turn each (no read-ahead).
- FreeDOS wins one test, 20 small files create + delete (16.7 s against
  Grid-OS 21.6 s), with as many writes (160 against 162): it is where the
  sectors sit on the turning disk (a turn is 200 ms).
  - Delete: Grid-OS writes the directory (side 1 sector 3), then the FAT
    copies at sectors 3 and 12 of side 0.  Two writes at the same angle,
    so 2 turns a file whatever the order (writing the FAT copies in the
    order the disk brings them was tried: 21.59 -> 21.49 s, not worth its
    144 bytes, dropped).  FreeDOS's files landed further out, so its FAT
    sector is 4, right after the directory's 3: 1 turn.  Layout luck.
  - Create: Grid-OS writes the FAT before the directory at close (a power
    cut can only lose clusters, never cross-link), so a close ends with the
    directory sector and the next create writes that same sector: a whole
    turn.  FreeDOS writes the directory before the FAT (less safe) and
    doesn't hit it.  Holding back the create's directory write until the
    close would save that turn (about 4 s here) and keep the safe order.
- EMS: Grid-OS maps a page 6.8x faster than EMM.SYS (42 us against 286 us
  in this CPU model) and moves 1.4x faster (2.9 MB/s against 2.1 MB/s).
  FreeDOS and MS-DOS both use EMM.SYS, so their EMS numbers are the same.
- Memory: with EMS, Grid-OS leaves the most (580.3 KB): 0.3.8 keeps its
  18 KB cylinder cache in two EMS pages.  Without EMS the cache is in
  conventional memory and GRiD MS-DOS leaves 16 KB more.  EMM.SYS takes
  7.3 KB; Grid-OS's EMS manager 1.9 KB.  FreeDOS leaves the least: on a
  286 there is no HMA or UMBs to load it high, and FreeCOM is large.
- The first run (0.3.7, cache in conventional memory) gave the same times
  to within 0.001 s; with EMS it left 562.5 KB.
