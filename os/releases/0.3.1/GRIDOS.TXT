Grid-OS 0.3.1 - boot floppy

First time only: boot GRiD MS-DOS from the EPROM as usual, then run
A:\GOSBOOT and answer Y. It adds the Grid-OS loader to this disk
and keeps all files.

To start Grid-OS: restart and tap F while the memory count finishes,
so the BIOS boots this floppy instead of the EPROM.

Grid-OS 0.2 is its own DOS 3.30-compatible kernel: files, directories,
programs (.COM and .EXE), memory, and the GPIB driver built in on
INT 60h (GRIDGPIB is not needed under Grid-OS).

0.2.1 adds a disk cache.  When a program reads a file in order, the
kernel reads the rest of that cylinder (both sides, up to 18 KB) in one
pass, so small reads no longer cost a turn of the disk each.  Writes
still go straight to the disk.  The cache takes 18 KB at the top of
memory: programs get about 570 KB.

0.2.2 adds a screen saver.  After 5 minutes without a key or the mouse
the Executive runs DEFRAG (if it is on this disk): it shows every
cluster of the disk and tidies it - deleted entries out of the root
directory, every file in one piece, free space at the end.  When the
disk is in order, the screen goes dark with just the time and date,
moving every 20 seconds, so the plasma never holds one picture.  Any key
or the mouse brings the Executive back (the key does nothing else).

0.2.3: when a read of several sectors keeps failing, the kernel reads
them one at a time before reporting a Data error.  A worn or dirty
drive head often can't get a whole track through, yet reads each
sector of it on its own.

0.3 starts the application suite.  The Executive now sits on a shared
UI core (lists, forms, windows, help, the line editor), and programs
written for it are .RUN files that load next to it:
  WRITE.RUN   Write, the text editor, after GRiDWrite.  Text, Source,
              Batch, Settings and Profile files open in it from the list;
              CODE-W starts a new file.  GRiDWrite's commands, verb first:
              press the command, select with the cursor keys or the mouse,
              then Return.  CODE-B Begin, CODE-D Duplicate, CODE-E Erase,
              CODE-F Find, CODE-J Jump, CODE-M Move, CODE-O Options,
              CODE-Q Quit (saves), CODE-S Substitute, CODE-T Transfer
              (save, write to another file, include a file), CODE-U Usage,
              ESC (or CODE-ESC) Cancel.  Files up to 64 KB; it saves to
              NAME.$$$ first, so a failed save leaves the old file alone.
  SYSTEM.RUN  Usage (CODE-U in the Executive): memory, disks, the clock
              (Return sets it), devices, GPIB (Return finds instruments
              by serial poll, then sets them back to local), display
              (Return switches the screen font), about.
Keep WRITE.RUN and SYSTEM.RUN in the root of this disk (or in the
subject you work in).  A DOS program gets about 569 KB: while it runs
the Executive lends it the memory of its file list.  The screen font is
GRiD's own: the InteGRiD system font (TC8X16), as GRID.EXE drew it.
TERMBOLD.FNT is the font Grid-OS had before; in System, Display, Return
switches between them (and any other .FNT in the root of the disk).  The
choice is kept in GRIDOS.INI as FONT=TERMBOLD.FNT; without that line, or
without the file, it is GRiD's.  CODE-? opens the help everywhere (F1 too).

0.3.1: DOS programs have the mouse too: Grid-OS answers the Microsoft mouse
calls (INT 33h) with its own serial-mouse driver, so no MOUSE.COM is
needed.  TM5000G says "Mouse support enabled." and menus take clicks.
The pointer shows in text modes and in CGA and GRiD graphics modes.
A program that never asks for the mouse leaves COM1/COM2 alone.

The Executive (the file list):
  Up/Down, PgUp/PgDn, Home/End   choose a file
  A letter                       the next name starting with it
  Return                         run it / open it / open a subject
  CODE-U                         Usage (SYSTEM.RUN)
  CODE-W                         Write a new text file (WRITE.RUN)
  CODE-A                         Claude (CLAUDE.COM)
  CODE-C                         command prompt (GRIDCMD.COM, EXIT returns)
  F5                             read the disk again after a swap
  CODE-? (Alt+/) or F1           help
  CODE-D                         boot GRiD MS-DOS from the EPROM
  CODE-R                         restart
  5 minutes idle                 screen saver (DEFRAG, then the time)
  Serial mouse on COM2 (or COM1).

Programs:
  GRIDCMD   the command prompt: DIR TYPE COPY DEL REN MD RD CD CLS ECHO
            VER VOL SET PATH PROMPT DATE TIME PAUSE REM EXIT, A:, programs,
            .BAT files, redirection < > >> and pipes |
  CLAUDE    Claude for GRiD. Needs the Pi bridge at GPIB address 7
            (CLAUDE /A:nn for another). F1 keys, CODE-Q quits.
  TM5000G   TM5000 3.7
  TESTDOS   checks the kernel's DOS functions (writes and deletes its
            own test files on this disk; "24 passed, 0 failed" is right)
  CACHETST  checks the disk cache: random reads and writes on two
            files, every byte checked ("0 errors" is right; about 400 KB
            free needed, a few minutes).  Results go to CACHETST.TXT too
  BENCH     file system benchmark: run it here, then under GRiD MS-DOS
            from this drive (B: there), and compare (about 400 KB free
            needed; some 5 minutes under MS-DOS).  Each run is added to
            BENCH.TXT on this disk; both wait for a key at the end
  GGTEST    GPIB driver test on the bus
  TESTKEY   echoes keys until Esc (for checking Claude's key scripts)
  GRIDGPIB  the GPIB driver for GRiD MS-DOS (load it first there)
  DEFRAG    tidies this disk (also the screen saver; DEFRAG /S as one).
            A file only ever moves whole: copied, read back and
            compared, then its directory entry is switched over, so a
            power cut or a pulled disk can't damage it.  It stops if the
            disk is changed; it only shows the map on a write-protected
            disk, under GRiD MS-DOS, or when files are open (run from a
            .BAT file).  Any key stops it.  Old disks wear: a bad spot
            in the free space gets its clusters marked bad (as FORMAT
            does) and it carries on; a weak sector in a file is read
            again and again, and the file moved to good ground.  Only a
            drive that can't write at all stops it.  Each run that
            changes the disk adds a line to DEFRAG.TXT on it
            DEFRAG /T tests all the free space and marks the bad spots
            DEFRAG B: (or B: /T) works on the floppy in drive B:
  HEADCLN   head cleaning with a wet cleaning disk: spins the drive and
            sweeps the heads for 30 s (HEADCLN B: 20 for drive B:, 20 s).
            It only reads; it asks for the cleaning disk and for your
            disk back, with a minute for the alcohol to dry

To update Grid-OS, replace GRIDOS.SYS (and GRIDCMD.COM, the .RUN files)
on this disk.
No need to rerun GOSBOOT.

Keep COMMAND.COM, CONFIG.SYS and AUTOEXEC.BAT off this disk unless they
are meant for GRiD MS-DOS: booted from the EPROM with this floppy in the
drive, GRiD MS-DOS uses A:\COMMAND.COM (and A:\CONFIG.SYS) in place of
its own.
